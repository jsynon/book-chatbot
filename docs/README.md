# Reading Companion architecture and development guide

The Antilogicalism Reading Companion helps readers move from a question to relevant passages in the library and back to the original books. The public site is a pilot for accurate, question-aware answers with citations. Treat answers as guides to reading: valid page links and model review do not guarantee that every claim is correct or complete.

Use the [live Reading Companion](https://jsynon.github.io/antilogicalism/reading-companion/) to ask a question, inspect cited passages, open the original PDF page, and continue with a follow-up.

## The three repositories

| Repository | Responsibility |
| --- | --- |
| [antilogicalism](https://github.com/jsynon/antilogicalism) | Static website, Bookshelf, Library Search, Reading Companion interface, and live evaluation workflows. |
| [antilogicalism-library-data](https://github.com/jsynon/antilogicalism-library-data) | Published catalog and v49 search data, extracted book pages, source fingerprints, and original PDF metadata. |
| [book-chatbot](https://github.com/jsynon/book-chatbot) | Cloudflare Worker API for the public pilot and a separate Python/Ollama workbench for local development. |

The repositories share published catalog and book data. The Worker does not host a second copy of the full library. The public site and local workbench use different answer-generation implementations, so a local answer is not a direct test of the live Worker.

## Public answer path

The live interface is in `antilogicalism/reading-companion/`. Its search module reads the published library index, finds candidate pages, and tags pages with the question parts that led to them. It sends the selected page text and locations to the Worker; the browser does not decide which text is trusted.

The Worker path in `hosting-poc/public-gateway.mjs` and `hosting-poc/evidence-answer.mjs` works as follows:

1. **Plan the question.** The planner identifies the reader's intent, named works or authors, question parts, and focused search queries. For broad conceptual questions, it can add a small number of clearly relevant context sources and distinct retrieval leads while keeping one central answer part; those sources are search context, not proof of the central claim or fixed routes to a particular answer. The planner keeps a single direct question as one coverage part unless the wording explicitly asks distinct questions, a comparison, or a multi-part hypothetical. For one-part questions, all planner queries remain linked to that part as optional retrieval leads, including conceptual wording with little lexical overlap; this grants candidate eligibility only and does not prove support or create another answer obligation. Contextual ideas remain search leads or supporting prose rather than becoming extra answer obligations. This remains one planner call. A broad, single-author topic remains one required coverage part; distinct model search leads may still help retrieve examples or qualifications. Author-wide questions keep that author's available works unless the reader names a distinctive work phrase; an author's name appearing inside a book title does not count as naming that work. For a hypothetical response between two thinkers, the plan assigns source-side parts and searches to each author's own works, then adds a synthesis part linked to both. When selected-books mode skips planning, the Worker reconstructs that bounded structure only if the question explicitly names exactly two authors present in the verified source titles; groups follow the question's author order and retain two premise parts plus one shared inference part. Other selected-book questions keep the existing one-part fallback. Selected-book requests stay within their selected books.
2. **Retrieve and select pages.** The browser searches the published v49 data and selects a bounded set of passages. The reader's query and the planner's queries are the lexical search inputs; the index does not append a topic-specific synonym list. Catalog aliases and author/title matches help resolve source metadata and scope, but they do not establish that a passage is relevant or who speaks in it. Explicit comparisons keep each side's queries within its resolved source group; a bounded local retry may reuse terms from the other side only inside the empty side's already-planned book IDs. This adds no model call or page budget. OCR index and publication pages are screened out of substantive evidence. Candidate merging reserves a returned eligible page for each question part when one exists before distributing additional pages across parts and works. After those per-part representatives, the deterministic selector ranks linked passages by an exact quoted-phrase match and the strongest local cluster of distinctive question terms, then uses the existing retrieval score. A different book is preferred only when the passage-fit signals tie; source diversity is not a quota. These lexical signals explain ranking behavior but do not establish semantic support. When a part's exact wording was searched globally but a linked planner facet resolved the part to catalog works, retrieval also searches that wording inside still-unsearched works. These scoped searches use the same answer-page limit. Each candidate records which question parts it may support. A part link is an eligibility hint, not proof that the passage supports an answer.
   The `compare-selection` benchmark adds an authenticated, evaluation-only model selector over the same retrieved candidate pool. It sees at most 48 bounded excerpts and can return only their temporary candidate IDs. Its mapped pages still pass through the existing six-page, request-byte, library-version, and fingerprint gates. It runs alongside the deterministic selector for measurement; the public chatbot does not call it. The experiment keeps retrieval misses distinct from selection misses.
3. **Verify source text.** Before inference, the Worker checks each submitted page against published SHA-256 fingerprints and obtains canonical book, page, and PDF metadata. A mismatch is rejected. The verified page identity and PDF link come from the published data, not from model output. The answer and review inputs also carry credited-author, editor, translator, planner-role, explicit page-heading context, and title-guarded known work/page voice metadata. Those fields guide attribution but do not prove who speaks in an individual passage. When a known editorial-commentary page is cited, the citation preserves the commentator separately from the book's credited author.
4. **Compose by question part.** The composer receives question parts and bounded, exact passage windows selected from the linked fingerprint-verified pages. Each selected window keeps one neighboring span on either side when available. The full page text remains in the authenticated trace and is used for review; lexical ranking only chooses what to show the composer and never counts as evidence validation. The authenticated trace also retains the full retrieved candidate set for diagnosis. Conditional gap-planner leads carry the weak part they were generated to address; the site preserves that link through candidate selection and reports whether linked candidates reach the submitted packet. A part link is retrieval bookkeeping, not a semantic support judgment. This keeps unrelated results from other books out of the shared prompt while preserving the retrieval record. It should answer each part directly in its first sentence, naming the requested concept or relation rather than relying on an unexplained pronoun-led opening. When asked what a phrase means, it should interpret the phrase before explaining consequences. If the supplied pages state the reason or premise that leads to the phrase's effect, the answer should preserve that causal step too, using adjacent supplied pages when they contain the needed context. It must not invent a reason when the packet does not establish one. For comparisons, it should state each author’s position in a separate sentence using that author’s relevant evidence, then synthesize only a relationship supported by both sides. When the question asks only for a comparison, it must not append a counterfactual about what one author might say if applying their view to the other; reserve that for an explicitly hypothetical question. For a substantive question with sufficient evidence, it should lead with a direct answer and aim for two to four developed paragraphs with distinct roles; a simple factual question or thin evidence still calls for a concise answer, without padding. Planner search queries remain retrieval leads rather than extra topics the reader asked to cover. Each factual sentence should make one main claim; use the smallest set of pages that directly supports that claim, rather than citing every retrieved page or every page by the same author. The composer should not bundle distinct assertions into one sentence. It must distinguish authorial text from pseudonymous voice, quoted or reported speech, narration, editorial introductions, translator notes, and commentary. A credited book author or planner role is not automatically the speaker on a page. It cites the page IDs that support each sentence. Unsupported parts remain visible as gaps.
5. **Validate citations and review.** Deterministic checks reject unknown, out-of-scope, wrong-book, or wrong-part source IDs. Multiword text presented as a quotation is checked against a cited page; short single-word terms are treated as terminology. Before review, a deterministic scope check removes a narrowly matched cross-author conditional transfer from an ordinary comparison while preserving independently supported comparison claims; explicitly requested hypotheticals retain their existing path. With review enabled, the existing second answer call assesses each cited sentence against exact spans from every cited source. Its compact input carries each part's bounded exact spans plus each claim's ranked same-source span hints and planner source groups. The hints guide review but do not limit it: the reviewer may select another span already supplied for that same cited source and part. The reviewer must check the same concept, speaker, action, polarity, qualification, and scope—not topical overlap—and return one source decision for every cited source. It checks phrase-meaning answers for an explicit interpretation and checks each author premise against that author’s evidence; synthesis requires support for the specific relationship asserted. If the supplied passage gives a causal premise for an interpretation, review checks that the answer preserves it along with the outcome, without demanding context that was not supplied. For each part, it must nominate the smallest set of direct-answer claims that covers the requested facets, not every claim by default. The reviewer now completes claim/source decisions before choosing that set; the Worker still requires every nominated claim to survive exact quote review. It removes rejected claims before final rendering; a rejected non-direct claim alone does not downgrade a part when the reviewer confirms the remaining answer is complete. A missing or rejected direct-answer claim, or an incomplete reviewer part decision, remains partial or unanswered. Review JSON may discard only a repeated closing delimiter that is structurally unmatched at that position, the exact syntax defect observed in paired run #9. The ordinary schema, claim IDs, source IDs, statuses, and exact spans are validated unchanged afterward; any other malformed or truncated output remains fail-closed with no retry call. The reviewer may select up to three spans per source and six per claim; the Worker validates every selected ID against fingerprint-verified text. A claim may omit a citation explicitly marked partial or unanswered, even when that decision contains no span IDs, only when the claim itself is answered, another cited source from the same planned group has an accepted exact span, and all source groups cited by the claim remain represented. Missing or malformed source decisions, a source marked answered without an accepted exact span, a legacy spanless decision, and loss of a comparison premise remain fail-closed. The final answer and evidence map include only retained, reviewed claims and citations. A deterministic high-precision guard also rejects a directly matched capability claim when the selected passage explicitly says the speaker cannot do that action but the answer says they can. This catches clear polarity reversals; it is not a general semantic entailment check.

   Known title/page-guarded editorial pages must be attributed to the commentator or introduction; known pseudonymous work voices must be identified. An accepted, reviewed attribution can carry across later answer parts, but an unsupported claim cannot establish that context. Direct author pages do not inherit an editorial label. For a hypothetical answer about one author responding to another, the inference must be standalone and cautious, with relevant evidence for each author's premise and a narrow shared point of contact. It cannot be phrased as a historical judgment. Unknown, duplicate, or missing decisions and source spans remain incomplete. One supported clause does not validate a different clause in the same sentence. Composer and reviewer instructions suppress unrelated topic lists and retrieval-process narration. If review output is cut off, the trace reports `review-output-truncated` and the answer remains unverified without another model call. Model review remains fallible; exact citation and highlight locations do not prove semantic support.
6. **Return readable evidence.** The Worker groups up to three reviewer-approved excerpts per cited page and returns at most six distinct cited pages. Each excerpt retains its claim and question-part links; a legacy primary `quote` remains for compatibility. It ranks the primary excerpt using both its linked claim and the reader's question so a directly relevant phrase can lead over nearby context. This only reorders already reviewed, exact spans. The site matches the answer sentence before an inline citation to those claim points and opens the matching excerpt set in the page reader. The reader highlights every exact, unambiguous excerpt it locates and leaves unmatched text unhighlighted. The source card can show each approved excerpt for that page. Lexical ranking, OCR normalization, and exact substring matching do not establish semantic support; only reviewer-approved spans are eligible, and model review can still be wrong.

The public pilot uses the evidence pipeline unless `READER_PIPELINE=legacy` selects the rollback path. Public requests remain behind the Worker’s origin, Turnstile, visitor-rate, global-rate, and source-fingerprint checks. Full prompts, full source pages, and raw model responses are available only through the authenticated evaluation trace, not the ordinary public answer.

### Model calls

The Worker uses Cloudflare Workers AI with Gemma 4 26B A4B for answer composition and review. The planner is a separate call. A reviewed question normally uses one planning call, one composition call, and one review call. The conditional search-gap planner is a separate, retrieval-only call made only when the site's text-coverage diagnostic remains weak; it suggests queries and cannot add answer obligations. The evaluation-only `with-expansion` variant adds a draft-expansion call between composition and review, so the existing reviewer checks the expanded prose. Ordinary public requests never enable this variant. The review is a fallible model judgment, not a truth certificate. Review output is bounded to 1,800 completion tokens; any truncation remains fail-closed and does not trigger a retry. Worker responses include the Cloudflare version ID and, when deployed with a 40-character Git SHA as the version tag, a validated `workerSourceRevision`. Deploy with the checked-out source SHA as the version tag. From the repository root in PowerShell, run `npx.cmd wrangler deploy --config .\hosting-poc\wrangler.public-pilot.jsonc --tag $sha`, where `$sha` is the 40-character SHA of the checked-out commit. Use the production config in your checkout; `wrangler.public.example.jsonc` is example-only. The live evaluator records the SHA in each case and the artifact's `workerSourceRevisions` list, independently of Cloudflare's deployment-generated version ID. A missing revision means the run cannot establish which Worker source was tested.

Planner endpoint failures include a fixed, sanitized failure stage and class in addition to the existing code, so the site can distinguish initial planning from conditional gap planning without exposing raw provider messages. Gap-planning failure continues with the original verified retrieval packet; no retry or citation-validation bypass is added.

The authenticated review trace now records each claim/source handoff: a bounded answer-claim excerpt, candidate span IDs sent to the reviewer, IDs it returned, the exact source span retained by deterministic validation, and any validation reason. Part decisions preserve the reviewer's status, the status after exact-span checks, and `outputStatus`, the status returned after final citation and required-answer validation. These can differ when composition removes a required sentence after review. When every composed answer sentence fails citation validation, the authenticated final trace summarizes the finite validation-reason codes; it does not add a model call or change the public failure response. Public highlights preserve the claim-to-quote relationship through the browser and bounded diagnostic summaries. This makes it possible to distinguish “the reviewer chose an unrelated span and the Worker accepted it” from “the reviewer chose valid evidence that still does not semantically support the claim.” The additional candidate and display grouping add no model call and do not expose the authenticated trace in public answers.

## Evaluation and quality limits

The website repository contains the live holdout and acceptance workflows. The consolidated answer-quality benchmark runs the approved calibration set or the frozen acceptance set in one dispatch, optionally uses a wider retrieval candidate pool, and can compare ordinary composition with evaluation-only post-composition expansion. It reports planner, retrieval, answer, and review progress while running. Authenticated runs can save exact prompts, model outputs, source pages, rejection reasons, usage, and final answers. Structural outcomes and semantic answer quality are separate: the workflow may complete with structural misses so the artifact can be reviewed; `qualityStatus` remains pending until the five human scores are entered. In selected-books mode, part alignment remains restricted to the expected selected works. In all-books mode, the audit accepts another work only when it appears in that part's planner `sourceBookIds`, still requires the configured expected work, and reports additional eligible works separately for answer-quality review. That eligibility check does not establish semantic relevance.

Use the [evidence milestone release report](reader-evidence-milestone-release.md) for the project history, decisions, workflow findings, current fixes, and remaining validation. The seven-question development set is diagnostic; it is not evidence of general performance because it has informed changes. Reserve the unseen acceptance set for a frozen candidate.

The pipeline can still miss a passage because retrieval is limited and language in a question may differ from the book's wording. OCR damage can make a verified page hard to interpret. Fingerprints prove that submitted text matches the published page text; they do not prove that the OCR is correct or that a claim follows from the page. Model review can miss errors or downgrade supported prose. Structural tests check contracts such as source IDs, scope, and part links; they cannot establish philosophical, historical, or literary accuracy. Inspect cited passages whenever the interpretation matters.

```

```

## Current answer-quality guardrails

Search planning does not append topic-specific query vocabulary after the model responds. The retriever preserves the planner's queries and searches the reader's direct question. The existing planner is guided to retain a direct query and use other query slots for distinct, relevant conceptual angles when useful. For a contemporary or specialized label, it may search the underlying concepts, assumptions, or reasoning found in differently organized source texts; those contextual leads are not direct evidence for the contemporary claim. The planner does not receive prescribed authors or works. If retrieved text has weak lexical coverage of a requested part, a second bounded librarian call may propose up to three optional search leads from a small set of retrieved excerpts. The coverage diagnostic checks whether distinctive question terms occur together inside one sentence or clause, rather than anywhere on a long page. It also recognizes index-like lists and prevents separate entries from combining into answer coverage. When an index page is the strongest lexical collision, the trace carries a bounded reason and source locator; those terms can help the librarian disambiguate a follow-up query, but the page is excluded from the answer packet. These are retrieval diagnostics, not semantic relevance judgments. The planner keeps surrounding context in alternate leads and may use source-native wording, but never prescribes authors or works. This conditional pass never changes the question parts or source scope, and overlap remains a retry trigger, not proof of relevance. Traces record matched terms, reason, locator, trigger, and both search passes.

The existing reviewer now has an explicit source-attribution decision for named-speaker claims. It should inspect the selected passage and nearby footnote/source-credit context before accepting claims such as “X taught…”; the trace records its attribution status and speaker. It also checks that negation scope is preserved: rejecting either of two alternatives must not be paraphrased as merely rejecting their conjunction. The composer leads with a primary text's direct account when later commentary is also available, then labels that commentary as a separate interpretation. A deterministic guard marks the detected negation-scope mismatch partial rather than allowing a located quote to imply semantic support. The composer can use two or three paragraphs and roughly 160–260 words when multiple relevant passages explain distinct facets, while remaining concise when support is thin. Length and source count remain diagnostics, not quality scores. The five human scores remain accuracy, question coverage, explanation quality, citation support, and citation completeness.

Source selection also suppresses near-identical passage copies when normalized work titles match, each passage has at least 40 tokens, and at least 94% of the shorter passage's three-word shingles occur in the longer excerpt. There is no page-length ratio requirement: editions may wrap the same passage in different surrounding text. Materially revised translations remain eligible when their passage shingles differ. Exact source fingerprints, scope checks, and claim review remain unchanged.

Offline regression coverage includes the planner's bounded output contract, the conditional gap-planner contract, edition-copy suppression, explicit insufficient-evidence phrasings observed in production, and quoted-speaker attribution conflicts. When the composer explicitly reports that supplied passages do not answer the question and no cited answer survives, the Worker returns the existing structured insufficient-evidence outcome with zero coverage rather than labeling that evidence gap as a format failure. The October 29 repeated calibrations showed both a local-window false negative and an index-entry false positive; sentence/clause matching and index-list exclusion address those distinct failure modes. Live acceptance evidence is still needed to determine whether retrieval and answers improve after deployment.

See [Question steering audit](question-steering-audit.md) for the cross-repository review of narrow runtime routes removed in this change and general evidence safeguards retained.

For a broad named-speaker question, a matching catalog author remains the preferred source identity. If the person appears in a work title instead, the Worker and browser use that title match only as a discovery and attribution check; it does not narrow every retrieval facet to one compiled text. When no source about the named person reaches the answer packet, the composer must not fill the gap with another author's topical passage. For fuller answers, two or three connected paragraphs and the non-binding 160–260-word guide apply only when distinct, relevant evidence supports separate facets. A distinct-work count and word count remain diagnostics, not goals.

## Separate local workbench

The repository also contains a Python application for local experimentation. It runs a local model through Ollama and does not call the Cloudflare Worker. On Windows, run `start.bat`; otherwise start it with `python app.py` and open `http://127.0.0.1:8765/`. Its developer view is at `http://127.0.0.1:8765/developer`.

For full-library local retrieval, the workbench needs local checkouts of `antilogicalism` and `antilogicalism-library-data` beside this repository. Follow the root [README](../README.md) for its setup. Local-model output tests the local pipeline only; use the website's authenticated workflow to test the public Worker.

**Guiding principle:** use AI to help readers find and understand the books while keeping the source text accessible and open to inspection.
