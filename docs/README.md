# Reading Companion architecture and development guide

The Antilogicalism Reading Companion helps readers move from a question to relevant passages in the library and back to the original books. The public site is a pilot for accurate, question-aware answers with citations. Treat answers as guides to reading: valid page links and model review do not guarantee that every claim is correct or complete.

Use the [live Reading Companion](https://jsynon.github.io/antilogicalism/reading-companion/) to ask a question, inspect cited passages, open the original PDF page, and continue with a follow-up.

## The three repositories

| Repository | Responsibility |
| --- | --- |
| [antilogicalism](https://github.com/jsynon/antilogicalism) | Static website, Bookshelf, Library Search, Reading Companion interface, and live evaluation workflows. |
| [antilogicalism-library-data](https://github.com/jsynon/antilogicalism-library-data) | Published catalog and v49 search data, extracted book pages, source fingerprints, and original PDF metadata. |
| [book-chatbot](https://github.com/jsynon/book-chatbot) | Cloudflare Worker API for the public pilot and a separate Python/Ollama workbench for local development. |

The repositories share published catalog and book data. The Worker does not host a second copy of the full library. The public site and local workbench use different answer-generation implementations, so a local answer is not a direct test of the live Worker.

## Public answer path

The live interface is in `antilogicalism/reading-companion/`. The browser performs lexical discovery over published v49 indexes, downloads candidate pages, and sends a bounded candidate pool to the Worker. It does not choose the final answer packet or decide which source text is trusted.

The Worker path in `hosting-poc/public-gateway.mjs` and `hosting-poc/evidence-answer.mjs` has five responsibilities:

1. **Plan once.** The planner identifies the request, its independently answerable parts when needed, and a small set of search queries. It separates distinct requested outcomes while keeping one relationship or a cause and its consequence together. The reader's question remains the anchor. Queries and source/title metadata help search, but they do not prescribe which authors the answer must cite.
2. **Retrieve broadly, then choose evidence.** The browser returns up to 24 candidate pages in the public baseline and up to 48 in the expanded evaluation profile. The Worker first verifies every submitted page against the published SHA-256 fingerprints. One semantic selector then reviews excerpts of up to 1,200 characters from those verified pages and chooses at most six pages that fit the existing answer byte limit. It classifies each selected page against each question part as direct or contextual, supplies a short excerpt that must match the candidate text, and treats a nonmatching excerpt as context rather than direct support. The selector also matches evidence to the requested answer operation: a rule or conclusion alone does not establish a requested explanation, and a comparison needs evidence for the relationship asked about. Lexical part links remain inspection hints only. If a structurally valid response names more pages than fit, the Worker keeps the selector's first choice for each nonempty part, then makes a breadth pass over the remaining ranked pages before filling any open slots in the original order. This is a soft preference for distinct works, not a per-work quota; repeated pages can still fill the packet when they are the only useful candidates. Unknown IDs and malformed fields still use the bounded fallback. The trace records each part’s selector cue, excerpt-match result, and any trimmed IDs. A valid empty selection remains empty and proceeds to composition, allowing a general answer without implying that retrieval found support. Technical selection failures retain the bounded retrieval-order fallback, marked with a safe failure reason in the authenticated trace; source-derived claims still go through exact evidence review. The selector cue guides composition but does not replace reviewer validation.
3. **Compose from selected text.** The composer receives only selected, verified pages, exact excerpts, source attribution metadata, and question parts. It writes a connected answer from those passages and can acknowledge gaps. If a model labels parts `PART 1`, `PART 2`, and so on, the Worker normalizes them only when they match the complete planned sequence in order; mixed, skipped, repeated, or extra numeric headings remain a traced format failure.
4. **Review and enforce integrity.** The reviewer checks answer coverage, cited claims, attribution, and exact evidence spans. It assesses uncited explanation collectively through the answer-part decision; when that part is accepted, the Worker retains the reviewed context together instead of letting separate uncited-claim labels strip the explanation after the whole part was accepted. Cited claims still require an explicit decision for every cited source, and an omitted source decision makes the review contract incomplete. The reviewer cannot verify general-knowledge claims against the book packet. Deterministic code enforces source fingerprints, page identity, scope, citation IDs, and exact quote locations. If the composer cites a passage locator such as `S2-Q8`, the Worker maps it to `S2` only when that exact locator exists in the current fingerprint-verified page; arbitrary or invented IDs still fail closed. These checks preserve traceability; neither a valid fingerprint nor model review proves that an interpretation is correct.
5. **Return inspectable citations.** The site links each cited claim to its approved source excerpt and original PDF page. Passage cards use the strongest exact reviewed excerpt for each answer claim on a page, joining adjacent spans for that same claim and avoiding lower-ranked filler excerpts. Authenticated traces record the retrieved candidate pool, selector decision, selected pages, composition, and review so a miss can be assigned to the stage where it occurred.

This separates three questions that were previously blurred together: did retrieval find useful text, did selection preserve it for the answer, and did composition explain it well? The wider retrieval pool costs more browser transfer, while the selector adds one model call; both remain bounded. The `paired-selection-ablation` workflow compares a six-page input pool with the full retrieved pool while keeping Worker selection, composition, and review the same. This identifies whether candidate recall or a later stage limits the answer.

The public pilot uses the evidence pipeline unless `READER_PIPELINE=legacy` selects the rollback path. Public requests remain behind the Worker's origin, Turnstile, visitor-rate, global-rate, and source-fingerprint checks. Full prompts, full source pages, and raw model responses are available only through the authenticated evaluation trace, not the ordinary public answer.

### Model calls

The Worker uses Cloudflare Workers AI with Gemma 4 26B A4B for planning, evidence selection, composition, and review. A reviewed question normally uses four model calls: one planner, one selector, one composer, and one reviewer. The conditional search-gap planner may add one retrieval-only call when text coverage is weak. The answer reviewer may add one targeted repair call only when it omits a cited claim/source decision; the repair receives only that claim, its cited source, and already verified review spans, and the original fail-closed decision remains if repair fails validation. The evaluation-only `with-expansion` variant adds an expansion call between composition and review; it is not enabled for ordinary public answers. Selection receives only fingerprint-verified candidate pages. Lexical retrieval's part hints help the selector inspect coverage but are not treated as evidence; the final composer and reviewer still use the six-page/35 KB answer packet. A part with no selected library evidence is explicitly reviewed as a qualified general-context answer rather than being rejected solely for the library gap. Review remains a fallible model judgment, not a truth certificate. Review output is bounded and scaled to the number of claims, with truncation remaining fail-closed. Worker responses include the Cloudflare version ID and, when deployed with a 40-character Git SHA as the version tag, a validated `workerSourceRevision`. Deploy with the checked-out source SHA as the version tag. From the repository root in PowerShell, run `npx.cmd wrangler deploy --config .\hosting-poc\wrangler.public-pilot.jsonc --tag $sha`, where `$sha` is the 40-character SHA of the checked-out commit. Use the production config in your checkout; `wrangler.public.example.jsonc` is example-only. The live evaluator records the SHA in each case and the artifact's `workerSourceRevisions` list, independently of Cloudflare's deployment-generated version ID. A missing revision means the run cannot establish which Worker source was tested.

## Evaluation and quality limits

The website repository contains the live holdout and acceptance workflows. The consolidated answer-quality benchmark runs the approved calibration set or the frozen acceptance set in one dispatch, optionally uses a wider retrieval candidate pool, and can compare ordinary composition with evaluation-only post-composition expansion. It reports planner, retrieval, answer, and review progress while running. Authenticated runs can save exact prompts, model outputs, source pages, rejection reasons, usage, and final answers. Structural outcomes and semantic answer quality are separate: the workflow may complete with structural misses so the artifact can be reviewed; `qualityStatus` remains pending until the five human scores are entered. In selected-books mode, part alignment remains restricted to the expected selected works. In all-books mode, the audit accepts another work only when it appears in that part's planner `sourceBookIds`, still requires the configured expected work, and reports additional eligible works separately for answer-quality review. That eligibility check does not establish semantic relevance.

Use the [evidence milestone release report](reader-evidence-milestone-release.md) for the project history, decisions, workflow findings, current fixes, and remaining validation. The seven-question development set is diagnostic; it is not evidence of general performance because it has informed changes. Reserve the unseen acceptance set for a frozen candidate.

The pipeline can still miss a passage because retrieval is limited and language in a question may differ from the book's wording. OCR damage can make a verified page hard to interpret. Fingerprints prove that submitted text matches the published page text; they do not prove that the OCR is correct or that a claim follows from the page. Model review can miss errors or downgrade supported prose. Structural tests check contracts such as source IDs, scope, and part links; they cannot establish philosophical, historical, or literary accuracy. Inspect cited passages whenever the interpretation matters.

## Current answer approach

Search planning does not append topic-specific query vocabulary after the model responds. The retriever preserves the planner's queries and searches the reader's direct question. The existing planner is guided to retain a direct query and use other query slots for distinct, relevant conceptual angles when useful. For a contemporary or specialized label, it may search the underlying concepts, assumptions, or reasoning found in differently organized source texts; those contextual leads are not direct evidence for the contemporary claim. The planner does not receive prescribed authors or works. If retrieved text has weak lexical coverage of a requested part, a second bounded librarian call may propose up to three optional search leads from a small set of retrieved excerpts. The coverage diagnostic checks whether distinctive question terms occur together inside one sentence or clause, rather than anywhere on a long page. It also recognizes index-like lists and prevents separate entries from combining into answer coverage. When an index page is the strongest lexical collision, the trace carries a bounded reason and source locator; those terms can help the librarian disambiguate a follow-up query, but the page is excluded from the answer packet. These are retrieval diagnostics, not semantic relevance judgments. The planner keeps surrounding context in alternate leads and may use source-native wording, but never prescribes authors or works. This conditional pass never changes the question parts or source scope, and overlap remains a retry trigger, not proof of relevance. Traces record matched terms, reason, locator, trigger, and both search passes.

The active Worker composer can use general knowledge to explain concepts and connect ideas even when the library has no direct passage. It should answer the reader's exact question before adding adjacent theories or analogies, and explain how those connections relate. Claims about a supplied book, author, speaker, or page use the Worker citation form `[S1]` (or `[S1, S2]` for multiple pages); titles and parenthetical source labels do not create a usable citation. Independent context and synthesis may remain uncited. The reviewer must not assume an uncited claim is general context when it attributes a position to a supplied source. It judges uncited context for directness, relevance, coherence, attribution, and completion; it checks cited claims against exact source spans, including speaker attribution, scope, and negation, but remains fallible. Single-part answers can be assigned to their only part when the model omits the heading, then pass through ordinary validation and review. Truncated drafts and answers ending in an unfinished lead-in fail closed. A source-free accepted answer is labeled as general context rather than as a verified source draft. Score source support separately from answer accuracy, question coverage, explanation quality, and readability. Citation completeness means appropriate citations on claims presented as source-derived, not a citation on every sentence. Longer prose is encouraged when it makes the explanation clearer, without a word-count target.

After semantic selection, the Worker suppresses a second page when either its normalized work title matches a selected page and the excerpts meet the existing 40-word/80% three-word-shingle threshold, or both Bible pages contain at least three of the same consecutive, explicitly headed canonical verses and the question does not ask for a translation comparison. Cross-version suppression also requires that numbered scripture make up at least 75% of each selected text, so commentary-heavy pages remain separate evidence. The Bible check uses verse structure rather than translation wording, allowing it to recognize the same passage across differently titled versions. The trace records the suppressed and retained candidates, the reason, text overlap or shared verse references, and scripture-text share; part links from a suppressed copy are carried onto the retained page. Exact source fingerprints, scope checks, and claim review remain unchanged.

Offline regression coverage includes the planner's bounded output contract, the conditional gap-planner contract, edition-copy suppression, explicit insufficient-evidence phrasings observed in production, and quoted-speaker attribution conflicts. When the composer explicitly reports that supplied passages do not answer the question and no cited answer survives, the Worker returns the existing structured insufficient-evidence outcome with zero coverage rather than labeling that evidence gap as a format failure. The October 29 repeated calibrations showed both a local-window false negative and an index-entry false positive; sentence/clause matching and index-list exclusion address those distinct failure modes. Live acceptance evidence is still needed to determine whether retrieval and answers improve after deployment.

See [Question steering audit](question-steering-audit.md) for the cross-repository review of narrow runtime routes removed in this change and general evidence safeguards retained.

For a broad named-speaker question, a matching catalog author remains the preferred source identity. If the person appears in a work title instead, the Worker and browser use that title match only as a discovery and attribution check; it does not narrow every retrieval facet to one compiled text. When no source about the named person reaches the answer packet, the composer must not fill the gap with another author's topical passage. For fuller answers, two or three connected paragraphs and the non-binding 160–260-word guide apply only when distinct, relevant evidence supports separate facets. A distinct-work count and word count remain diagnostics, not goals.

## Separate local workbench

The repository also contains a Python application for local experimentation. It runs a local model through Ollama and does not call the Cloudflare Worker. On Windows, run `start.bat`; otherwise start it with `python app.py` and open `http://127.0.0.1:8765/`. Its developer view is at `http://127.0.0.1:8765/developer`.

For full-library local retrieval, the workbench needs local checkouts of `antilogicalism` and `antilogicalism-library-data` beside this repository. Follow the root [README](../README.md) for its setup. Local-model output tests the local pipeline only; use the website's authenticated workflow to test the public Worker.

**Guiding principle:** use AI to help readers find and understand the books while keeping the source text accessible and open to inspection.


### Handoff validation

The one-run **Reading Companion handoff validation** workflow in the website repository tests five cases after the planner and retrieval-coverage updates are deployed: three open-ended All Books questions and two selected works. It includes the technology-change and Odyssey handoffs as regression checks, with three additional questions to check that the changes generalize. It is a live, manually dispatched test and should run once after both repositories are merged and published. The browser-side coverage signal now requires at least two distinct terms and 35% of the question's distinctive terms to co-occur in coherent prose. Every part's ratio, matched terms, threshold, and reason are recorded. A replay of the 45 attempts in the three saved fresh-set artifacts raises gap-planning triggers from 6 to 15; the new suite should show whether the extra retrieval calls recover useful evidence. This is only a conditional search trigger: it does not declare a source relevant or require another model call when coverage is already strong. Review answer quality, source relevance, citations, and whether the additional search was justified from the artifact.

The latest saved handoff trace exposed an All Books scope leak: “change” in the technology-change question matched the last word of a corporate byline and restricted search to one work. The site now requires a recognizable author mention before author-based scope is applied. Worker planning guidance now distinguishes separate requested outcomes from a single causal or explanatory relationship, and the shared plan normalizer preserves a multi-part planner decision for a coordinated question instead of collapsing it through a narrow surface-form list. These changes add neither a new answer route nor a model call.
