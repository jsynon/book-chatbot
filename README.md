# Antilogicalism Reading Companion

The Antilogicalism Reading Companion is an experiment in making the ideas in books easier to explore. It lets readers ask questions in ordinary language, get an answer grounded in passages from a book, and follow citations back to the relevant PDF pages.

## Part of the Antilogicalism project

[Antilogicalism](https://jsynon.github.io/antilogicalism/) brings together essays, reading resources, and a growing library of books for exploring philosophy and related subjects. The Reading Companion adds a conversational way to enter that library: readers can ask about a concept, trace an argument through a text, or use citations to return to the original passage. Its purpose is to support close reading and further thought, not to replace the books or the broader site.

Book text is maintained separately in the [`antilogicalism-library-data`](https://github.com/jsynon/antilogicalism-library-data) repository. Keeping the corpus there gives the library one shared source of truth as it grows. The companion is a separate application that can use those texts to find passages and build answers.

## Current prototype

The current pilot works with Aristotle's *Nicomachean Ethics*. It is a step toward the larger goal of making the same reading experience work across the Antilogicalism book collection; it is not yet connected to the full library. The project is testing whether a locally run language model can answer a range of questions while keeping its claims connected to passages readers can inspect.

The app searches the book text, drafts a response from relevant passages, and checks the response's claims and quotations before displaying citations. Before skipping a broader search, retrieval checks that its best passages cover multiple topical terms in a multi-concept question, rather than treating a generic wording match as sufficient. For argument questions, passage ranking also recognizes topic-matched statements about what an activity or pursuit aims at, so premises stated as purposes can surface alongside passages marked by “because” or “therefore.” When a question asks both for a result and how the author argues for it, the leading retrieved passage stays first and a passage with a topic-matched conditional and its result is moved into second position when available. This gives models a clearer chance to see the claim and its reasoning together; the evidence checker still has to validate the answer. For questions with multiple parts, it also runs a separate local search for each part and labels passages with the part that found them, helping the model keep a conclusion, its reasoning, and other requested details distinct. When a later part uses a pronoun such as “it” or “this,” retrieval carries the topic from the preceding part into that local search so an argument search stays connected to the idea the reader asked about. When an expanded search finds a clearly stronger new passage, it can move that passage ahead of the weakest direct result while keeping the direct results available to the model. A long PDF page can contain several separate paragraphs, so retrieval can keep a second strong, non-overlapping passage under the same page citation; this avoids losing useful evidence to page-level deduplication without adding duplicate page links. Retrieved passages show source and page labels separately from the book text, helping models quote the text without copying locator details into citations. The answer and checking prompts distinguish a limit in the retrieved passages from a claim that the book never discusses a subject. For hypothetical questions about what an author would think, a specific judgment must cite an excerpt that names the topic being judged; otherwise the companion reports that the passages do not establish the author's view. When an answer clause names two or more concepts from the question, the cited excerpts must include wording for each named concept, so a quote about one idea cannot silently support an added claim about another. Quotations are checked against the complete retrieved passage. If a model inserts one extra article into an otherwise exact short quote, the checker can remove that article only when every remaining word forms an exact, contiguous source excerpt; the quote then passes through the usual evidence checks. If a model returns an overlong quote that exactly matches a passage, or preserves at least twelve consecutive words from it, the checker can select a shorter exact window from that same citation, with nearby wording included when needed to support the claim. When a short exact quote is too narrow, the checker may widen it with adjacent words from that same passage only when the resulting exact excerpt substantially covers every claim clause and named topic anchors. The troubleshooting report records whether quote repair succeeded and how the excerpt changed. This repair still has to pass the normal evidence checks. The evidence checker reserves more response space for answers with several separately cited parts and increases that allowance in bounded steps when a model response is cut off, so a repair has more room to finish its structured output. If a fresh reconstruction returns malformed JSON after a validation failure, it can use its final bounded attempt to rebuild from passages alone rather than stopping before the repair. ## Run locally

1. Install [Ollama](https://ollama.com/) and download a model, for example with `ollama pull qwen3:4b`.
2. Extract this project. To use a separate `antilogicalism-library-data` checkout, place it beside the project folder or configure the data path as described in [`data/README.md`](data/README.md).
3. Start Ollama, then double-click `start.bat`.
4. Open `http://127.0.0.1:8765` in your browser and choose an installed model.

The app uses Python's standard library and does not require a hosted AI API key. Its model selector discovers the models installed in Ollama and passes the selected model to the shared retrieval, answer, and evidence-checking flow; the project is not hardwired to Qwen. The current model connection is Ollama-specific, so another inference provider would need its own adapter. Models may differ in how well they follow the prompts and return structured evidence, so the same regression questions should be tested with each candidate model. The app listens only on the local computer and sends questions and retrieved passages to Ollama running there. It is a local research prototype, not an online chatbot.

The regression runner submits five repeatable questions to one or more installed models in sequence, limiting each paired run to five questions per model. The set keeps two useful baselines (practical wisdom and the mean relative to us), retains the God-and-soul completeness check, and explores friendship alongside a rotating topic from another part of the book. This replaces the earlier nine-question set to reduce run time while sampling different question types and parts of the book. After each run, the page shows a compact result for every model and question, including the final outcome, its main issue, and a separate attempt history. The downloaded JSON report includes these summaries along with the full retrieved passages and checker trace. The runner defaults to Qwen 3 4B and Llama 3.2 3B when both are installed, and you can select any installed Ollama model. The report is downloaded to the local computer and is shared only if you choose to attach it. These repeatable prompts help track changes across builds, while improvements are made in the shared retrieval, answering, and evidence-checking pipeline rather than in responses to individual questions.

```bat

It does not measure how well a live model follows the prompts. Use the in-app regression runner with the models you want to compare for that part of development.
