# Antilogicalism Reading Companion

The Antilogicalism Reading Companion is an experiment in making the ideas in books easier to explore. It lets readers ask questions in ordinary language, get an answer grounded in passages from a book, and follow citations back to the relevant PDF pages.

## Part of the Antilogicalism project

[Antilogicalism](https://jsynon.github.io/antilogicalism/) brings together essays, reading resources, and a growing library of books for exploring philosophy and related subjects. The Reading Companion adds a conversational way to enter that library: readers can ask about a concept, trace an argument through a text, or use citations to return to the original passage. Its purpose is to support close reading and further thought, not to replace the books or the broader site.

Book text is maintained separately in the [`antilogicalism-library-data`](https://github.com/jsynon/antilogicalism-library-data) repository. Keeping the corpus there gives the library one shared source of truth as it grows. The companion is a separate application that can use those texts to find passages and build answers.

## Current prototype

The current pilot works with Aristotle's *Nicomachean Ethics*. It is a step toward the larger goal of making the same reading experience work across the Antilogicalism book collection; it is not yet connected to the full library. The project is testing whether a locally run language model can answer a range of questions while keeping its claims connected to passages readers can inspect.

The app searches the book text, drafts a response from relevant passages, and checks the response's claims and quotations before displaying citations. Before skipping a broader search, retrieval checks that its best passages cover multiple topical terms in a multi-concept question, rather than treating a generic wording match as sufficient. For argument questions, passage ranking also recognizes topic-matched statements about what an activity or pursuit aims at, so premises stated as purposes can surface alongside passages marked by “because” or “therefore.” When a question asks both for a result and how the author argues for it, the leading retrieved passage stays first and a passage with a topic-matched conditional and its result is moved into second position when available. This gives models a clearer chance to see the claim and its reasoning together; the evidence checker still has to validate the answer. For questions with multiple parts, it also runs a separate local search for each part and labels passages with the part that found them, helping the model keep a conclusion, its reasoning, and other requested details distinct. When a later part uses a pronoun such as “it” or “this,” retrieval carries the topic from the preceding part into that local search so an argument search stays connected to the idea the reader asked about. When an expanded search finds a clearly stronger new passage, it can move that passage ahead of the weakest direct result while keeping the direct results available to the model. A long PDF page can contain several separate paragraphs, so retrieval can keep a second strong, non-overlapping passage under the same page citation; this avoids losing useful evidence to page-level deduplication without adding duplicate page links. Retrieved passages show source and page labels separately from the book text, helping the model quote the text without copying locator details into citations. The answer and checking prompts distinguish a limit in the retrieved passages from a claim that the book never discusses a subject. For hypothetical questions about what an author would think, a specific judgment must cite an excerpt that names the topic being judged; otherwise the companion reports that the passages do not establish the author's view. Quotations are checked against the complete retrieved passage. The evidence checker reserves more response space for answers with several separately cited parts and keeps a bounded output increase for later repair attempts after a response is cut off. If a fresh reconstruction returns malformed JSON after a validation failure, it can use its final bounded attempt to rebuild from passages alone rather than stopping before the repair. For ordinary questions, it rejects a long answer sentence copied word-for-word from a source passage and asks the model to synthesize the point; readers who explicitly request a quotation can still receive source wording. For argument questions, the checker uses fixed JSON fields for the conclusion and reasoning so the model cannot omit one by assigning both items the same role label. The reasoning can combine a textual starting point with the inference, and its claims and quotations still pass the same evidence checks as other answers. For comparison questions, the app keeps each idea in a separate answer item, requires a cited excerpt that names the idea, and checks each claim clause against an individual excerpt. A brief phrase such as “distinct from” may name the counterpart to state the relationship, while descriptions of each concept's properties stay in their own separately evidenced item. This helps prevent a quote about one concept, or pooled wording from separate excerpts, from making an unsupported comparison look grounded while allowing concise comparisons to read naturally. These checks can catch some unsupported claims, but they cannot guarantee that every interpretation is correct. Readers should use the source links to check context, especially when an answer explains a complicated argument or connects ideas across passages. Source links open the Google Drive preview instead of downloading the PDF; Drive may open at page 1, so use the physical page number shown with each citation to navigate within the preview.

## Run locally

1. Install [Ollama](https://ollama.com/) and download a model, for example with `ollama pull qwen3:4b`.
2. Extract this project. To use a separate `antilogicalism-library-data` checkout, place it beside the project folder or configure the data path as described in [`data/README.md`](data/README.md).
3. Start Ollama, then double-click `start.bat`.
4. Open `http://127.0.0.1:8765` in your browser and choose an installed model.

The app uses Python's standard library and does not require a hosted AI API key. Its model selector discovers the models installed in Ollama and passes the selected model to the shared retrieval, answer, and evidence-checking flow; the project is not hardwired to Qwen. The current model connection is Ollama-specific, so another inference provider would need its own adapter. Models may differ in how well they follow the prompts and return structured evidence, so the same regression questions should be tested with each candidate model. The app listens only on the local computer and sends questions and retrieved passages to Ollama running there. It is a local research prototype, not an online chatbot.

The regression runner can submit five repeatable questions to one or more installed models in sequence. After each run, the page shows a compact result for every model and question, including the final outcome, its main issue, and a separate attempt history. The downloaded JSON report includes these summaries along with the full retrieved passages and checker trace. The prompts cover practical wisdom, the highest human good, a comparison of kinds of wisdom, the role of habituation in forming virtue, and a broad question about God and the soul. This gives the pilot checks across Books I, II, and VI, including whether a model uses a limited textual mention without claiming the book says more than the passages support. The runner defaults to Qwen 3 4B and Llama 3.2 3B when both are installed, and you can select any installed Ollama model. The report is downloaded to the local computer and is shared only if you choose to attach it. These repeatable prompts help track changes across builds, while improvements are made in the shared retrieval, answering, and evidence-checking pipeline rather than in responses to individual questions.

## Development

Run the retrieval and citation checks from the project folder:

```bat
py -3 -m unittest discover -s tests -v
```

The automated suite uses mocked Ollama responses, so it checks retrieval, answer structure, quotation matching, citations, and interface behavior without requiring a running model. It does not measure how well a live model follows the prompts. Use the in-app regression runner with the models you want to compare for that part of development.
